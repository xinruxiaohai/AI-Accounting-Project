## 为什么归档而不是删除

1. **可溯源**：比赛或答辩被问「这个设计是什么时候定的、当时怎么权衡的」，这些文件是第一手证据。
2. **防误引**：它们描述的是**当时**的结构（例如 `prd-v0131.md` 中的任务编号 T01–T05 与现在的代码已不完全对应），放在根目录容易被当成现行规范。
3. **减噪**：`docs/` 根目录只保留 4 个「必读」层级——交接、日志、技术报告、演示脚本，加两个目录（`prompts/`、`bugs-and-solutions/`），评委不必在一堆 v0.13.x 设计稿里找入口。

## 使用提醒

- 引用归档文件时，请**显式带上 `docs/archive/` 前缀**，避免读者以为它在根目录。
- 归档文件**不再随版本更新**。若某条设计后来被推翻，正确做法是在 `../dev-log.md` 对应版本记录「推翻了什么、为什么」，而不是回头改归档稿。
