# 16 · AI 意图路由、快记弹窗与报销闭环

## 需求背景

AI 只能记账，用户说“借给小王 20”“添加联系人老李”时会被硬套成支出；顶栏单行输入框也不适合多行描述。另一边，出差、团建这类先自己垫付、后统一报销的支出，只能混在总支出里，看不到“待报销”和“已报销”各多少。

## 核心 Prompt

“把 AI 升级成意图路由：先判断用户的话是记账、借贷、添加联系人还是听不懂，只抽对应字段，统一返回带 action 的 JSON；后端按 action 分流写库，借贷找不到联系人就自动建，听不懂返回 400。前端把顶栏输入框换成「+ 记一笔」旁的「AI 快记」按钮，点开 Bootstrap 弹窗，多行输入、发送转圈、按 action 弹 Toast、Esc 关闭、Ctrl+Enter 发送。账单详情加报销开关，开启后选报销人和金额，资产页显示待报销与已报销金额，报销不能影响账户余额。”

## AI 方案简述

模型层从单一 parse_record 拆成 parse_intent，输出固定带 action，四个分支各自归一化：记账沿用原有的字段校验，借贷强制要姓名与借出/借入并映射成 lend/borrow，添加联系人只要姓名（电话、微信可选），听不懂直接抛错。后端用 action 分流，借贷按姓名精确匹配联系人、没有则创建并在写库失败时回滚，避免留下空联系人。

报销单独开一个接口只改报销字段：只允许支出账目，金额不超过账目本身，已报销不能大于报销总额，关闭开关时四个字段一起清零。账户余额仍是唯一真相，报销动作不碰余额与统计口径，资产页的待报销/已报销完全由账目字段汇总得出，不额外存冗余总额。

前端弹窗用 Bootstrap Modal，提交时按钮转圈并禁用，成功后关窗、按 action 换文案、刷新看板；听不懂时保留原文方便用户改写。详情弹窗里的报销区随开关展开，报销人从通讯录下拉选，金额默认全额。

## 踩坑结论

GLM-4-Flash 会把姓名里的“测试”前缀、数字当废话删掉，提示词必须明确“姓名原样保留、不得删字”，否则测试联系人名字对不上。

Bootstrap 在弹窗开合动画进行中会直接忽略 hide()，刚打开就点保存会出现“数据已写入但弹窗不关”；处理方式是保存后补一次延时重试关闭，仍以数据落库为准。

意图路由的提示词里同时放四个分支的字段，模型容易把别的分支字段也吐出来，所以归一化时每个 action 只取自己那组键，其余一律忽略。
