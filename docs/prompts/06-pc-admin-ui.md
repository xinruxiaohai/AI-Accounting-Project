## 一、这一步要解决什么

v0.03 的界面是「一个卡片列表页」，能用，但不像一个后台系统；时间只精确到天，晚上记的两笔账分不出先后。
这一步同时动三处：

- **时间粒度**：账目时间从 `YYYY-MM-DD` 升级到 `YYYY-MM-DD HH:MM`，且老数据不能丢；
- **界面形态**：从单页卡片改成左侧深色侧边栏 + 右侧主内容区的 PC 后台布局，记账入口收进弹窗；
- **功能补全**：编辑 / 删除 / 资产页（账户余额编辑）/ 日历页（当月支出网格）全部接上真实接口。

约束是硬要求：不刷新页面，点完「保存」卡片和表格必须自己变。

## 三、AI 给出的方案要点

### 后端：时间归一（database.py / app.py）

| 位置 | 职责 | 关键写法 |
| --- | --- | --- |
| `normalize_date(value)` | 读时归一 | `strip().replace("T", " ")`；长度 ≤ 10 补 `" 00:00"`；否则截 `text[:16]` |
| `add_record` / `update_record` | 写时归一 | 入库前统一走 `normalize_date(date)` |
| `list_records` | 读时归一 | `[dict(row)]` 之后逐条覆盖 `record["date"]`，**不改库里的物理值** |
| `_parse_datetime(value)` | 解析 + 报错 | 空值取 `now()`；长度 10 按纯日期解析；否则依次试 4 种带时分格式，失败返回 400 |
| `index()` | 默认值 | 多传 `now=datetime.now().strftime("%Y-%m-%dT%H:%M")`（`T` 是 `datetime-local` 的格式要求） |

选择「读时补全」而不是「写时批量 UPDATE」的理由：迁移只需要一行代码、可回滚、无 DML，失败也不会留下半张表被改过的状态。

### 前端：布局分层（templates/index.html + static/style.css）

| 层 | 元素 | 样式要点 |
| --- | --- | --- |
| 外壳 | `.app` | `display:flex; height:100vh; overflow:hidden` |
| 侧边栏 | `.sidebar` | `flex:0 0 220px`、`#1e293b`、`.nav-item.active` 蓝底白字、`:hover` 半透明白 |
| 主内容 | `.main` | `flex:1; min-width:0`，防止长表格把布局撑破 |
| 顶栏 | `.topbar` | 固定 64px、白底、`box-shadow`，左标题右主按钮 |
| 滚动区 | `.content` | `flex:1; overflow-y:auto` —— 只有这里滚，侧栏和顶栏不动 |
| 弹窗 | `#record-modal` | `modal-dialog-centered`，`datetime-local` 默认 `{{ now }}` |

Bootstrap 体积大（CSS 232803 B / JS 80721 B），用 `static/vendor/` 本地引用换取「断网可复现」，比赛现场网络不可控。

### 前端：数据流与交互（static/script.js）

- `refresh()` = `Promise.all([loadStatistics(), loadAccounts(), loadRecords()])`：一次刷新三块数据，三者互不依赖，可以并行。
- 写操作成功后**只重拉数据、不 `location.reload()`**，卡片、表格、资产页、日历同步更新。
- 编辑复用同一个弹窗：`editingId` 有值走 `PUT`，无值走 `POST`；标题与按钮文案随状态切换。
- 表格行与账户行都是动态生成的，用**事件委托**绑在 `tbody` 上，重渲染不会丢监听。
- `ensureOption()` / `clearTempOptions()`：分类「卫浴」不在后端下拉选项里时，临时插一个 `option[data-temp="1"]`，否则 `select.value = "卫浴"` 静默失败，编辑会把分类改成第一项。
- 日历不额外请求接口：复用 `allRecords` 按 `date.slice(0,10)` 聚合当天支出。

## 六、踩坑与结论

- **`datetime-local` 只认 `T` 分隔**：既然后端同时收空格与 `T`，前端就直接发 `2026-10-26T14:30`，省一次字符串替换；但回填时必须把库里的空格换回 `T`，否则输入框显示空白，看起来像「时间丢了」。
- **迁移优先「读时补全」而不是改数据**：`ALTER TABLE` 加列已经是低成本操作，但批量 `UPDATE date = date || ' 00:00'` 是不可逆的数据改写；读时归一秒回滚，代价只是每次列表多一次字符串拼接。
- **`select.value = 不存在的值` 不报错**：赋值失败时 `value` 变成空串，用户看到的是「分类莫名变了」，排查成本极高。给编辑流程加 `ensureOption()` 是必要的兜底，不是过度设计。
- **动态行必须事件委托**：早期实现是渲染完逐行 `addEventListener("click")`，每次 `refresh()` 后旧监听跟着旧节点一起被丢掉，表现为「刷新一次后删除按钮失效」。改成绑 `tbody` 后一次解决。
- **DOM 桩测试的价值与边界**：桩能覆盖 34 条业务断言（请求体、状态切换、渲染字符串），但看不到 Bootstrap 弹窗动画、真实点击、CSS 布局。所以必须补一次真浏览器渲染复核，两者互补。
- **headless 输出要按 UTF-8 读**：`--dump-dom` 写出的文件用 PowerShell 默认编码读会把 `¥` 读成乱码，导致「明明渲染了却断言失败」。同一个坑在 curl 输出与 Python 控制台上出现过两次（GBK 控制台），统一约定：所有中文输出显式指定 UTF-8。
