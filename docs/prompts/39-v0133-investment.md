# 39 · v0.13.3 投资账户体系、双视图看板与 AI 深度适配

## 需求背景

记账应用只有"现金类账户"，用户想记基金/股票持仓只能自己写在备注里。
本版要引入投资账户：子平台（天天基金、蚂蚁财富）、持仓、定投计划，并在资产页右侧给一个独立看板（持仓 / 流水双 Tab）。
同时要让 AI 听懂「买入 1000 元易方达蓝筹」和「从微信转入 5000 到天天基金」两种说法。

## 核心 Prompt（要点，非原文）

1. `accounts` 支持 `type='investment'`；新增 `invest_platforms` / `holdings` / `dca_plans`，**幂等迁移不影响旧数据**
2. Mock 行情 `/api/invest/search?keyword=`，`price` 字段预留真实行情
3. 投资账户仍可正常写入/查询 `records`（转入转出流水）
4. AI 识别 `invest_buy` 直接写 holdings；`transfer` 写 records；气泡流引导确认
5. 点投资账户 → 右侧独立看板；双 Tab 默认【持仓】；ticker 小字灰色显示；当日盈亏占位 `+0.00 (0.00%)`；子平台折叠；新建持仓防抖搜索

## 方案简述

### 数据层
- `invest_platforms` 用 **`account`（账户名）** 而不是 `account_id`——`accounts` 主键是 `(user_id, name)`，**没有单列 id**。与全项目 `records.account` / `debts.account` 同口径，零重建表
- 迁移挂在 `_migrate_category_isolation()` 之后、第二段 DML 之前：SQLite 的 DDL 隐式提交，必须与其它 DML 分开；且要给投资账户补「默认」子平台，必须早于种子 DML
- **回填用 `schema_migrations` 标记位**，不能用"刚补列那一轮"判断——那种写法遇到"先落列、后补迁移函数"的库会永远不执行，且无法自愈

### 资金口径（决策 B）
```
accounts.balance = 可用资金（永不包含持仓市值）
买入：写/加仓 holdings + 扣 balance，不写 records
清仓：按 cost_total 退回 balance
勾稽：可用资金 + Σ持仓成本 = 累计转入 − 累计转出
```
选"不写 records"而不是"写 expense 投资买入"，是因为后者会让「买入 1000」凭空把本月支出推高 1000，而这不是支出。

### AI 双路径
SSE 与**非流式兜底**两条都必须短路返回 `200 + need_confirm`，且都放在 `_duplicate_candidate` 之前（防重按「金额+商户相似」比对 records，对投资意图会误判）。

## 踩坑结论

| 坑 | 结论 |
|---|---|
| **金额从来不是扣款依据** | 入库侧 `buy_holding()` 是优先级 if/elif 链，组合1「`amount = shares×price`」恒命中。前端三个数全发且归一化后恒 >0 时，**用户说的金额每次都被丢弃重算**。模型吐矛盾三元组 → 卡片显示 1000、实际扣 500 |
| **归一化与入库必须同构** | 只在中间夹一行校验不够，要把推导表在 `_normalize_invest` 里镜像，让两层走同一套规则 |
| **金额只能推导，不能假设** | `amount` 缺失且无单价时，不许用 `price=1.0` 编金额（用户说"买 100 份"可能实际花 ¥450，编 1.0 会只扣 ¥100 却记 100 份）。反之 `amount` 有值时可用 `price=1.0` 占位，因为钱是用户认过的 |
| **fallback 分支可能是死代码** | `amount <= 0` 在函数第一句就 raise，新加的兜底分支根本到不了。改推导链前必须先把守卫挪到末尾 |
| **不能靠 `price === 1.0` 判断"是兜的"** | 货币基金净值恒为 1.00，会把真实单价一起藏掉。必须由后端显式产出 `price_assumed` |
| **非流式兜底路容易漏** | 只给 SSE 加 `need_confirm`，一旦 SSE 失败降级到 `/api/records/ai`，投资指令就被吞成「AI 无法理解您的指令」 |
| **平台字段源头是 LLM** | `parsed.platform` 不能"没命中就自动建"，用户说「用余额宝买」时余额宝多半是普通账户，会造出删不掉的脏分组。v0.14 按「命中就用、没命中回落默认」 |
| **迁移回填依赖 `group_name='投资账户'`** | 所以账户大类下拉里那个选项**不能删**，否则老账户语义断掉；只能做联动 |
| **`current_price` 必须恒存 0** | 读取时回落 `cost_price`，市值才等于投入。谁让它开始存候选报价，市值立刻虚盈 113% |
| **`record_id` 是死列** | 决策 B 下恒 NULL，将来做「删账目联动清仓」或 CSV 回溯按它反查会静默返回空集 |
