# 46 · v0.15 多智能体并行 / 识别精度 / K 线 / 协作防冲突

> 说明：本快照根据 v0.15 四个并行 Agent（A 移动端、B 文本、D 图像、E 投资）的真实任务与结果复盘整理，
> 属「要点整理」而非逐字原文；核心 Prompt 尽量保留下达时的关键约束措辞。

## 一、需求背景

v0.14.3.4 之后同时压来四块工作：移动端头像/筛选体验、AI 文本与图片识别不准、
截图先压缩导致文字糊、投资模块缺 K 线。工作量与领域跨度都超出单轮，故拆成 A/B/D/E 四个 Agent 并行。
并行立刻暴露新问题：`ai_service.py`（B/D 共用）与 `app.py`（D/E 共用）被覆盖两次——D 的压缩函数
先被 E 的 K 线代码整段抹掉，补救后又被第二次覆盖。这成为本轮最值钱的教训来源。

## 二、核心 Prompt（要点）

**任务下达的共同骨架**（每个 Agent 第一轮都带）：

> 开工前先读 `docs/HANDOFF.md` 的「二、并行 Agent 协作声明」段，只改你白名单内的文件，
> 共用文件按声明顺序串行改，谁都不许自行 bump 版本号，测试产物一律放 `D:\Project\temp` 各自子目录并建索引。

**分派约束的原文要点**：

1. 给 B：「只改 ai_service.py 的 SYSTEM_PROMPT 与文本归一化区，不碰 VISION_PROMPT/parse_image（D 的范围）」。
2. 给 D：「改 ai_service.py 的 VISION/parse_image 与 app.py 图片路由(约1752-1875)、script.js 上传入口；
   图片测试走 parse_image() 纯解析层，避免 app.py 往项目 static/uploads 落盘」。
3. 给 E：「只改 app.py 投资路由区(约3138+)、invest-v0133.js、K 线 Modal；前端只改 templates/ 与 static/」。
4. 补救时：「只改 app.py 图片相关的行（62 行常量 + 图片路由区），绝对不要碰 3200+ 的 K 线路由和
   `_invest_kline_cache`——那是 E 的成果；改完 grep 双向标记自检」。

**用户拍板版本时的关键一句**：「把版本号统一定为 0.15」——此前 A/B/D/E 被明令禁止 bump，
由协调方一次性把 20 个文件 118 处旧标记统一替换，避免四个 Agent 各改一半造成版本分裂。

## 三、方案简述

- **协作声明写进交接文档**：在 `docs/HANDOFF.md` 新增「二、并行 Agent 协作声明」段——五方分工白名单表 +
  五条铁律（只改白名单、共用文件串行、禁 bump、测试隔离、git 只 add 自己文件），并规定「给任一 agent 下任务时
  提示词必须加一句『先读本段』」。这是把口头分工变成可被机器读到的硬约束。
- **文件白名单 + 行号锚点**：分派时不止说文件名，还标出区块行号（图片路由 1752-1875 / 投资路由 3138+），
  让「不要碰对方区块」成为可执行的 grep 断言，而非道德要求。
- **红基线 → 改动 → 同判据复跑**：B 的文本、D 的图像都要求 before/after 用同一份脚本与判据，
  准确率数字可对比（图像 4/10→10/10）；E 的 K 线用接口 38/38 + vm/echarts-stub 做替代验证。
- **版本由单点统一**：并行期全员禁 bump，收尾由协调方一处替换 + 一次提交 + 一次部署，避免四个 Agent 版本打架。

## 四、踩坑结论

1. **多 Agent 共用同一文件必然覆盖**，两次覆盖都发生在 `app.py`。「告诉对方别碰」不够——必须
   ①文件白名单到行号区块；②改完 grep 自身标记 + 对方标记**双向**确认；③收尾由协调方统一做一次合并确认。
2. **「先压缩后识别」是精度杀手**：原图 341KB 直送视觉模型，人名/金额/时间全对；先 Canvas 压缩再送，
   同音字与分类开始漂。正确顺序是「原图识别 → 识别成功后服务端压缩落盘」，Pillow 缺失时降级原图而非回滚账目。
3. **真机验收的权限坑**：workspace-write 沙箱下 Chromium mojo 管道被拒，Node vm+ECharts stub 能做逻辑替代，
   但 canvas/坐标轴/tooltip 的真机断言必须 full-access 或现成浏览器端口——替代表验不能冒充真机验收。
4. **环境误判要只核实**：B 一度认定 venv 解释器失效、改用 Python3.13 + 占位 openai + urllib 复刻链路；
   协调方实测 `.\venv\Scripts\python.exe` 可正常 import ai_service。复刻链路能出结果，但结论要用真实 venv 复核。
5. **版本号必须全局一次替换**：只看 `APP_VERSION_FALLBACK` 会漏掉 SW/模板/manifest——曾出现「后端 3.4、
   前端 3.5」的半拉子状态。收尾 grep `0.14.3.x` 全项目 0 残留才算统一完成。
6. **封版文档是硬约束**：HANDOFF 红线要求每次封版同步更新「当前版本/下一步计划」+ prompts 快照 + dev-log；
   并行期最容易只顾代码忘了文档，本轮由协调方在部署后补齐。
