# 09 · 表单校验与交互细节（Prompt 快照）

## 一、这一步要解决什么

账目、账户、分类三套表单此前只有后端校验：

1. 金额留空、填 0、填负数，都要等提交后由接口返回 400，用户看到一句 Toast 才知道哪里错了。
2. 分类没选、账户没填时也能点保存，弹窗关到一半才报错，已填的内容全丢。
3. 保存按钮可以连点，同一笔账被提交两次；网络慢时页面没有任何「正在保存」的反馈。
4. 弹窗只能用鼠标关，键盘用户要按 Tab 找到右上角的 ×。

这一步把校验前移到输入框旁边，并补齐提交中的状态与键盘快捷键。

## 二、用户原始 Prompt（摘录）

> 现在点保存经常弹一个红 Toast 说参数不对，但我根本不知道是哪个框填错了。
> 要求：① 每个必填项旁边直接显示红字原因，错在哪一眼看见；② 金额必须是大于 0 的数字，公式算不出来也要当场提示；③ 保存中按钮转圈并禁用，防止连点重复记账；④ 记账弹窗 Enter 提交、Esc 关闭；⑤ 全部提示继续用 Toast，不许出现 alert。

（Prompt 为要点摘录，非逐字。）

## 三、AI 给出的方案要点

### 校验分层

| 层 | 做法 | 为什么 |
| --- | --- | --- |
| 输入时 | `input` / `change` 事件清掉该字段的旧错误 | 用户改对了就立刻消失，不用等再次提交 |
| 提交前 | `collectRecordValues()` / `collectAccountValues()` 返回 `{values, issues}` | 前端一次收集完，所有错误一起标出来，而不是改一个报一个 |
| 提交时 | 后端仍做同样的校验并返回 400 | 前端校验只是体验，安全边界永远在后端 |

### 错误提示

- 每个字段下方固定一个 `.field-error` 容器，文案如「金额要大于 0」「请选择分类」「账户不能为空」。
- 出错的输入框加 `.is-invalid`，边框转红；`reportIssues(modal, issues)` 统一写入并聚焦第一个错误字段。
- 公式算不出结果时（`Number.isFinite` 为假或 ≤ 0），金额框下方红字提示，不发请求。

### 提交中的状态

- `lockAction(key)` / `unlockAction(key)` 维护一个进行中的动作集合，重复点击直接忽略。
- `setButtonBusy(button, true, "保存中…")` 把按钮文字换成 spinner + 提示，并 `disabled`；`finally` 里恢复，异常也不会卡死。
- 表格加载用 `beginTableLoad(tbody, colspan)` 先铺骨架行，避免旧数据与新数据之间闪白。

### 键盘

- 记账弹窗：Enter 提交（焦点在 textarea 时不抢）、Esc 关闭。
- 详情弹窗：Esc 关闭、Enter 进入编辑。
- 所有弹窗关闭后把焦点还给触发按钮，Tab 顺序不乱。

## 四、结果

- 三套表单的错误都能定位到具体字段；连点保存只会产生一条记录。
- 前端自检 30+ 条断言通过，接口层非法请求仍稳定返回 400。
