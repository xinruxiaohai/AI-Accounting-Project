### 去重设计（按优先级实现，禁止用图片相似度当主判据）

**L1 字节级（成本≈0，必做）**
- 上传时对**原图 bytes** 算 `sha256`，命中同 uid 已有记录 → 直接返回 `{"duplicate": "exact", "record_id": N}`，不落盘、不调模型、不建记录。

**L2 交易指纹（主力）**
- 优先用**交易单号**：微信「交易单号」28 位、支付宝「订单号」、财付通「商户单号」。单号相同 = 同一笔，**跨截图稳定、零误判**。
- 无单号时用三元组：`(amount 取两位小数, date 截到分钟, 对方/商户名归一化)`；命中 → `{"duplicate": "possible"}`，**默认不写入**，返回给前端让用户确认，**绝不静默丢数据**。
- 指纹 = `sha256(uid|type|amount|date_min|trade_no or counterparty)`，**必须带 uid**，绝不跨用户比对。

**落库（幂等补列，禁止 create_all / 加外键 / 加索引）**
- `records.image_hash TEXT NOT NULL DEFAULT ''`（L1）
- `records.trade_no TEXT NOT NULL DEFAULT ''`（L2，OCR 出来的单号）
- 照 `categories.icon_key` 的写法走既有 ALTER 补列；旧记录留空，**不做启动时全盘回填**（另给一次性脚本，手动跑）。

**接口返回**
- `POST` 图片上传/识别成功后，响应体加 `duplicate: {kind: "exact"|"possible", distance: 0|N, record_id, summary}`；前端（`static/script.js` 上传入口）弹确认卡：「这张截图你 11-15 已记过 ¥11.93 拼多多，仍要新建吗？」默认「不新建」。
