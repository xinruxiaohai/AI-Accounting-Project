前端与缓存-05-SW 双份版本号不同步导致代码不生效

问题表现：

改完 CSS / JS 之后强刷页面，样式和逻辑依然是旧的。最典型的一次是「侧边栏折叠按钮怎么改都是右对齐」——源码里已经是 `justify-content: flex-start`，浏览器计算样式却还是 `flex-end`，换浏览器、清 localStorage 都无效。

排查过程：

先怀疑 CSS 特异性，逐条 `getComputedStyle` 打印，发现加载的规则顺序和本地文件对不上。

把浏览器里实际加载的 `style.css` 拉出来与磁盘文件比对，内容差了好几个版本 → 说明浏览器拿的是缓存。

继续查缓存来源：`Network` 面板里该请求显示 `(from ServiceWorker)`。而项目里有**两份** service-worker：

```
/service-worker.js          ← 根路径，浏览器注册的就是这个 URL
/static/service-worker.js   ← 实际被发版修改的副本
```

当时的 `app.py` 直接把根路径当成静态目录发文件，浏览器加载到的是**根目录那份旧副本**；而每次发版改的却是 `static/` 下的新副本，两者的 `CACHE_NAME` 从此长期不一致：

```js
const CACHE_NAME = "ai-accounting-v0.14.0-tst5";  // static：一直在改
const CACHE_NAME = "ai-accounting-v0.13.8-r1";    // 根目录：一直没动
```

SW 的静态资源策略是 stale-while-revalidate：命中缓存后**立刻返回旧文件**，后台再去更新。根目录那份的 `CACHE_NAME` 永远不变，于是缓存永远命中，新代码要等下一次协商才有机会生效——表现为「改了跟没改一样」（同样的坑也发生在 `manifest.json` 上）。

还有一个放大器：模板里的 `?v=` 资源串没有跟着 bump。SW 是拿完整 URL（含 query）当缓存键的，`?v=` 不变、`CACHE_NAME` 也不变，等于双重保险都锁死。

解决方案：

1. **根治：让根路径只发唯一版本**（v0.14.0 已落地）。`app.py` 的两个路由改为从 `static/` 目录取文件，根目录副本不再对外服务：

```python
@app.route("/service-worker.js")
def serve_service_worker():
    response = send_from_directory(
        os.path.join(BASE_DIR, "static"), "service-worker.js", mimetype="text/javascript"
    )
```

`/manifest.json` 同样处理。这一步做完，「改 static 不生效」这类问题才不会复发。

2. **在根治之前（以及现在防误改），两份文件必须同步改**，改完用一条命令交叉核对：

```bash
grep -n "CACHE_NAME =" service-worker.js static/service-worker.js
```

3. `CACHE_NAME` 与模板 `?v=` **同时 bump**，一次击穿两层缓存：

```bash
const CACHE_NAME = "ai-accounting-v0.14.0-tst5";
?v=0.14.0-tst5      # 模板与 manifest 全部资源串
```

4. SW 的 `install` 里先删同名缓存再重建，避免「版本号回退」（比如 r2 改回 r1）导致同名旧缓存复活：

```js
self.addEventListener("install", function (event) {
  event.waitUntil(
    caches.delete(CACHE_NAME).then(function () {
      return caches.open(CACHE_NAME).then(function (cache) { /* 逐个 add */ });
    })
  );
});
```

5. 验收脚本里先注销 SW + 清 Cache API，再 `Page.reload({ ignoreCache: true })`，否则测的仍然是缓存：

```js
await evaluate(`(async () => {
  const rs = await navigator.serviceWorker.getRegistrations();
  await Promise.all(rs.map(r => r.unregister()));
  const ks = await caches.keys();
  await Promise.all(ks.map(k => caches.delete(k)));
})()`);
await send("Page.reload", { ignoreCache: true });
```

教训：

「改完没生效」在前端有 90% 的概率不是逻辑问题，而是缓存问题，而且这个项目的缓存有四层（HTTP 缓存、SW Cache Storage、`?v=` 资源串、`CACHE_NAME`）。真正的元凶是「同一个文件存在两份」这种结构性问题——**光同步版本号只能治标，把路由收敛到唯一副本才治本**；在收敛之前，任何一次发版都必须把两份当成同一个文件对待。
