AI 图文识别准确率优化与免费 API 限制突破记录



一、 问题背景与现象



在接入智谱 GLM-4-Flash（文本）和 GLM-4V-Flash（视觉）免费大模型后，系统在实际测试中暴露了以下严重问题：



识别准确率低下：上传微信、支付宝或银行卡截图时，经常出现金额提取错误、商户名称漏提，甚至把“微信零钱”识别为“微信”等碎片化账户。



免费 API 限制阻断：免费 API 存在严格的并发限制与网络超时阈值。当用户一次性上传多张图片，或上传原图（几 MB 大小）时，极易触发 429（请求过多）报错或请求超时（502/Timeout），导致记账失败。



二、 根因分析



视觉幻觉与版式干扰：大模型在面对包含大量文字、数字、订单号的长截图时，注意力机制容易被干扰；同时，免费视觉模型的 Token 处理能力有限，输入画质过差会导致误判。



工程架构缺失：前端直接并发压缩并上传原图，瞬间打满网络带宽并触发了后端的并发限制。



记忆复用率低：每次请求都是独立无状态的，AI 无法记住用户之前对“账户名”或“分类”的纠错习惯。



三、 采取的优化措施



措施一：前端极致压缩与串行队列（解决 API 超时与并发限制）



图片动态降维：使用 Canvas 在前端将图片最大宽高限制在 1600px，JPEG 质量设为 0.9，在保证文字清晰度的同时，将 Base64 体积压缩至安全范围（< 2MB）。



任务串行化（重点）：废弃 Promise.all 并发上传。用户勾选多张图片后，前端通过 for...of 循环配合 await，逐张进行压缩和请求。气泡实时显示“正在识别 1/3”，彻底解决了 429 限流和后端阻塞问题。



措施二：特征级 Prompt 注入（解决版式干扰）



在 System Prompt 中强制输入视觉规则。例如：“微信截图顶部通常有绿色图标；金额通常在图片中上部且字号最大；如果存在‘实付金额’和‘优惠前金额’，必须提取实付金额。”通过给 AI 戴上一副“特征眼镜”，大幅降低了视觉幻觉。



措施三：本地 Difflib 相似度兜底（解决账户名幻觉）



由于模型可能返回“威信”、“微信零前”等不精确词汇，我们在后端引入了 Python 标准库 difflib。



当 AI 返回的账户或联系人名与数据库中已有名称的相似度大于 80% 时，系统静默强制覆盖，并在前端气泡用灰色小字提示用户：“识别到相似账户，已自动匹配为‘微信’”。这有效防止了账户碎片化。



措施四：RAG 动态少样本检索（让 AI 越用越准）



为解决无状态问题，新建了 ai\_memory 纠错记忆表。每次解析前，利用 SQL 关键词模糊查询（LIKE），从记忆中检索出与当前输入最相关的 Top 3 条历史纠错记录，作为 Few-Shot 示例动态拼接到 Prompt 中。这不仅极大提升了准确率，还避免了把整张表塞入 Prompt 造成的 Token 浪费。



四、 优化成果



准确率突破：通过特征 Prompt + RAG 记忆注入，复杂截图的金额与商户识别率大幅提升；相似度匹配机制让账户名混乱问题彻底清零。



零成本高并发：通过前端串行队列与动态压缩，系统在免费 API 的单并发限制下，依然能稳定、流畅地完成多张图片的连续录入。



体验闭环：新增“置信度预警”，当 AI 把握不足（分数低于 80）时气泡变黄提示核对，结合用户在气泡内的多轮纠错，实现了从“AI 自动处理”到“人机协同反馈”的完整闭环。
