测试与安全-01-测试脚本污染真实数据

问题表现：
前端自检脚本跑完后，真实数据库中的一条用户记录（“早餐测试”）被意外删除。排查发现删除接口本身没有 Bug，是测试脚本清理测试数据时误杀了真实数据。

排查过程：

测试脚本逻辑是：POST 一条测试数据 → 取 GET /api/records 返回的列表第一条 → 进行断言 → DELETE 删除。

某次跑测试时，POST 请求因参数问题失败返回 400，未成功落库。

随后的 GET 请求中，records\[0] 指向了列表原本最上方的真实记录（用户刚存的早餐）。

由于断言碰巧通过，脚本执行了 DELETE，删除了真实记录。

解决方案：

测试数据必须注入唯一标识，并用该标识回查，绝不依赖数组下标：
const note = \_*selftest*${Date.now()};
await api("/api/records", jsonOptions("POST", { ...payload, note }));
const mine = state.allRecords.find((r) => r.note === note);

添加严密的断言顺序：必须先断言 POST 返回状态码为 201，再断言 mine 存在，两者成立后才允许执行后续的 DELETE 操作。

发生误删后，立刻根据原有字段重建数据，并在开发日志中记录。

教训：
真实环境中的列表第一条永远是用户数据，而不是测试数据。涉及写数据库的自检脚本，必须按生产代码的标准来写，数据定位、断言校验、测试清理三步都要有严格的隔离机制。
